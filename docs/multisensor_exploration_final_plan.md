# Autonomy 室内多传感器自主探索建图：最终设计审查稿

版本：v2.15-review；日期：2026-11-18。本稿给出供审定的最终目标设计；正式部署证据对应 v2.12 NavigationTask 批次。v2.15 派发门控已在本地接入并通过隔离编译和原有导航专项，新增派发竞态及正式消费者部署仍待验证。

本文给出可逐项审查的目标设计。已实现范围单独列在 §15；其余接口、算法条件和验收要求属于实施目标。详细算法及历史证据见 [详细设计](multisensor_exploration_design.md)，26 类异常情形及交互审阅入口见 [方案总览](multisensor_exploration_review.md)。

**核心方案：保留 FAR 的增量可见性图路线机制与 TARE 的全局/局部分层覆盖框架，适配 Autonomy 原生任务系统；现有 GridMap/Costmap 保持不变；Opt 调整观测目标位姿；冻结 DeFM 与经过三模态适配训练的 SanD 式 B 样条局部策略共同支撑执行，独立几何 Safety 拥有最终否决权。**

## 1. 任务范围与固定选择

- 面向地面机器人、单层室内、与起点连通的允许区域，按明确的空间分辨率、观测方向和质量要求探索建图。
- 支持 `lidar_only`、`rgbd_only`、`lidar_rgbd`。每种模式有独立可用的定位链；任务不隐含额外 IMU、轮速计或可转动相机。
- 路线插件为 `VistaPlanner`，实例名 `vista_planner`，目录为 `autonomy/planning/planner/vista/`；探索位于 `autonomy/task/exploration/`，核心策略为 `HierarchicalCoverageStrategy`。
- 使用原生 C++、Autolink、Protobuf、Autonomy BT，遵循 `.hpp/.cpp`、snake_case 路径和现有嵌套命名空间。
- `autonomy/map` 的代码、目录、接口和消息定义全部保持不变。版本、差分、观测账本和局部执行几何由 map 外的消费者维护。
- 初始任务默认几何覆盖；类别语义、RGB 纹理、跨楼层和操作开门需要单独能力与验收。早期 VNT-PA 姿态记忆方案不进入本版依赖。

任务启动时冻结允许范围、覆盖分辨率、质量要求和来源政策。传感器掉线、深度孔洞或候选采样失败都不能自动缩小原任务要求。

“探索建图”分开验收三个产品：机器人可达自由空间的发现、所需几何表面的有效观测、上游地图融合与持久化。已走过地面不表示墙面已充分建图；室内未进入的房间也不能因门口没有局部 frontier 而被排除。仅 LiDAR 可以满足几何目标，不能满足要求 RGB 纹理的任务。任务将这些覆盖要求、可观测范围与排除政策明确列出。

## 2. 架构与所有权

```text
3D LiDAR / RGB-D
    │ 标定、真实采样时间、有效掩码、健康状态
    ├── 定位建图 ──→ 现有 GridMap / Costmap
    │                         │ 安全读取、消费者快照与差分
    │                         ▼
    │                Vista 增量 visibility graph
    │                         │ 路线与访问成本
    ├── 原始几何 ──→ 覆盖账本 ──→ 分层覆盖策略
    │                                      │ ObservationGoal
    │                                      ▼
    │                              Opt 调整并复核观测要求
    │                                      │ 委托导航
    └── 深度视图 ──→ 冻结 DeFM ──→ 模态条件融合 / B 样条扩散
                                           │ 物理时间、边界衔接
                                           ▼
                               独立 Safety ──→ 高频跟踪与底盘
                                           │ 反馈、实际观测
                                           ▼
                            覆盖兑现 → 完成复核 → 返航 → 保存
```

`PlannerServer` 持有一张长期 Vista 图。普通导航和探索均向这个所有者查询路线；独立 task/planning 进程通过 Autolink 服务通信。同进程注入可以复用实例，跨进程不能共享插件指针。

`ExplorationTask` 拥有一个 Session 和一棵 Tree；Session 统一提交探索导航、观测与收尾请求。策略、Opt 和 BT 选点节点只提出意图。探索父任务持有运动资格，委托导航继承该资格，由原生调度器识别父子关系。

上游定位建图或 `MappingTask` 负责更新、融合与保存地图。控制侧维护局部三维执行证据，覆盖侧维护历史观测证据，二者不替代现有 map owner。

## 3. 三种传感器模式

**仅 3D LiDAR。** 使用真实扫描束、水平/垂直视野、量程、回波有效性与采样时间；不假定所有型号具有完整 360° 视野。点云和射线直接用于几何覆盖、遮挡和 Safety。学习支路投影为带标定、视角及有效掩码的虚拟透视深度。射线量程需要转换为相机轴向 Z；未命中像素保持未知。定位链必须在没有相机或额外 IMU 的配置下仍可工作。

**仅 RGB-D。** 使用相机内外参、米制深度和 RGB-D 里程计/SLAM。候选包含机器人位置与 yaw，固定相机 pitch 来自安装外参。深度孔洞、透明、反光、量程外与不可见部分保留未知。到达位置后仍需确认相机方向、有效帧、停留和实际覆盖。

**LiDAR 与 RGB-D 联合。** 按各自采样时间变换到统一位姿基准；LiDAR 去畸变使用可用的时序位姿。分别计算真实视野，几何按稳定单元去重。超龄输入退出当前执行证据；有效 occupied/free 冲突保守处理并安排重新观测。

`configured_mode` 与本周期 `active_sensors` 分开。联合模式降级继续要同时满足：剩余观测有效、定位有效、控制后端支持剩余模态、Safety 能验证当前执行。模式滞回稳定配置状态，不能延长过期证据的有效期。全部观测或定位失效时停止新运动；旋转也需验证机器人扫掠体。

默认 `GEOMETRY_ANY_SENSOR`：任一允许来源可兑现一份几何覆盖。同一单元的重叠不重复计分。配置 `GEOMETRY_PER_SENSOR` 或多方向要求时，来源、方向、独立帧和质量分别记账；掉线不会删除未兑现要求。

## 4. 地图零改动与消费者增量

`perception/data/map_reader` 通过现有安全入口取得拥有内容的不可变快照；解锁后比较分区，生成消费者侧 `map_epoch`、`geometry_revision`、`dirty_regions` 与分来源观测截面。

需要验证读取的数据确实来自在线建图，而非未更新的静态地图。地图发布时间变化不等于几何变化；整图时间戳也不能刷新旧 free/occupied 单元的观测年龄。只有二维地图时明确缺少高度证据，三维净空由原始观测补充。

既有 GridMap 管理规划用地面、障碍与代价，消费者维护稳定覆盖单元及 frontier/区域状态，控制侧维护局部高度和三维净空证据。保留这三种产品的来源与时间关联：单张 2D GridMap 不承担完整室内三维表面模型；DeFM token 不替代任何一项几何证据。

滚动窗口移出不删除历史覆盖、连接或未完成要求。回环与坐标重置推进 epoch，可靠变换后复核图和证据，否则重建受影响状态。未知、无效、未观测与已知 free 必须区分。

第一版可以安全拷贝现有图并在消费者侧比较差分，从而增量更新 visibility graph。全图读取与比较的成本仍须计入延迟和内存预算。

## 5. Vista 增量可见性图

节点来自障碍轮廓拐点、通道连接及临时起终点，保留稳定 ID；边携带验证版本、几何来源与可通行/待验证状态。

更新过程为：变化区域定位 → 局部轮廓提取 → 稳定节点匹配 → 受影响边验证 → 断边或重连 → 发布新图版本。边空间索引必须查询穿过变化区域的长边；仅查询端点会漏掉中段新增障碍。障碍移除后重新检查曾被阻挡的连接。

足迹膨胀只应用一次。图查询失败时用已知空间栅格连通搜索复核；图采样不足不构成物理不可达证明。高层可保留带未知段的尝试性路线，当前运动只执行已验证近端，并在安全观测位置更新环境。

规划查询有取消、版本兼容与截止时间。图只由一个更新所有者修改，查询使用只读视图或受锁保护的数据。跨进程路线返回 request、frame、epoch 和图版本。

## 6. 分层覆盖与效率

全局 `RegionManager` 管区域、覆盖进度、入口和重访；`VisitOrderOptimizer` 使用 Vista 的真实路线成本优化访问顺序，计入转向、观测时间、重复覆盖与返航成本。

局部 `ViewpointSampler` 采样安全位置及 yaw，`ViewpointEvaluator` 计算可见性和有效质量改善；先硬筛选，再选择边际覆盖候选集并优化访问次序。每选一个候选更新预计覆盖并集，后续候选只计算增量贡献。

低收益角落、小 frontier、暂时受阻与尚未评估区域进入独立公平队列。分页保存游标与证据，地图变化只重开受影响项。启发式候选耗尽后，对明确的离散位置/方向空间进行扫尾与栅格复核。处理预算结束不能等同于没有剩余任务。

效率通过分层排序、图/候选局部重算、覆盖去重、特征缓存和目标切换滞回来提高。返航预算使用从下一目标回起点的可通行路线；返航连通性无法确认时停止向外扩展。启发式路线不承诺全局最优。

## 7. 信息增益与候选排序

第一版信息增益定义为**预计有效覆盖质量改善**，属于几何与质量代理。没有经过校准的后验和传感器似然时，不将它称为严格 Shannon 熵下降。

对候选位姿 q、已经选择的候选集合 S 和覆盖类型 k：

```text
G_k(q | S) = Σ_i A_i W_i [max_s(V_i,s(q) Ĉ_i,s(q)) - B_i(S)]+
G(q | S)   = Σ_k λ_k G_k(q | S) / Z_k
U(q | S)   = G(q | S) / (T_travel + T_turn + T_observe + ε)
```

`i` 是稳定覆盖单元；`A_i` 是面积或固定标准化单元，`W_i` 是任务权重；`V` 表示视野、量程与遮挡；`Ĉ` 是按任务质量要求归一化的预测完成程度；`B_i(S)` 是实际已得与已选候选预测的最大完成程度；`[x]+ = max(0,x)`。`Z_k` 在任务启动时固定，用于归一化不同覆盖类型。原始点数不直接代表面积。

质量与可见性考虑距离、入射角、采样密度、有效深度/回波、定位误差、运动模糊/去畸变和历史预测失败。未知遮挡后方不算确定可见收益；门口潜在拓展价值、等待时间与公平性单独进入调度政策。

`V` 必须先应用真实传感器模型：RGB-D 检查相机视锥、深度范围、投影与遮挡；LiDAR 检查真实束角、垂直盲区、回波与射线遮挡。未知空间采用预计可新增观测的保守代理，不假定未知处已有可验证表面法向。表面质量项只有在相应几何与法向有证据时使用。联合模式中的遮挡和质量分别估计，再按任务要求融合。

ANY_SENSOR 对同一单元取来源 max，是保守去重；互补视野通过不同单元产生额外收益。PER_SENSOR 对每个必要来源分别计算正改善，并按固定来源数归一化。必要方向、独立帧数和停留不能由另一来源或高总分抵消。

例如原始质量要求为 0.8，实际已得 0.6；候选预测 0.4 的改善为 0，预测 0.7 的归一化改善为 0.125。质量改善为零不代表方向或独立帧要求已经兑现。

不可达、净空不足、任务约束不满足、预算不足或证据过期的候选先被硬过滤。到达后只凭真实有效观测更新账本，同时记录 `predicted_gain` 与 `realized_gain`，用差异检查收益模型。

## 8. Opt 最佳目标位姿自适应调整

输入 `ObservationGoal` 表达原始位姿、允许区域及位移/yaw 范围、目标 region/frontier、必要覆盖单元、required_views、最低质量/收益和要求版本。

Opt 在有限候选中验证足迹、垂直净空、已知可达性、预算与观测约束，再按收益、路线成本和调整代价选择最高分。适配后重新计算路径与可见性；安全可停靠但看不到指定区域的点不能替代原观测目标。“最佳”限定为本次候选集合及约束下的最优评分。

三种状态的语义为：

- `POINT_GOAL`：目标及观测条件已确认，可以按该目标执行。
- `REGION_FALLBACK`：在任务允许的替代区域中找到仍能兑现原观测要求的位姿。
- `UNKNOWN_APPROACH`：目标信息不足，先去已知安全的观测位姿取得证据；未知原始点仍是任务意图。

每轮处理地图/观测变化。unknown → free 后重验目标；unknown → occupied 后搜索允许替代；障碍移除后重开相关任务。路径暂时受阻先重规划、等待或有界恢复，保留仍有效的观测意图。封闭房间或长期遮挡保留未确认项，门口到达不等于房间完成。

任务状态由运行时可观测证据驱动，不能读取仿真真值来决定行为。`FREE` 单元不自动证明整个位姿可达：机器人足迹、三维净空、路径、证据年龄和必要观测仍须独立验证。目标本身有效但通路受阻时保留目标；感知超时则报告观测不足，不将未知改写为已确认不可达。区域替代只有在任务显式允许且观测要求仍可兑现时才成立。

## 9. DeFM、SanD 与训练

DeFM 全程冻结，锁定权重摘要与官方预处理版本。每个新视图编码一次并缓存时间、位姿、标定、模态和掩码；历史窗口复用缓存。原始深度与射线保留用于覆盖和 Safety，DeFM 特征不直接证明自由空间或类别语义。

起步采用一套共享的模态条件投影/融合与 B 样条扩散头，数据包含 LiDAR 稀疏虚拟视图、RGB-D、联合输入、孔洞、异步、模态缺失及运动反馈。三种模式分别验收；更换原感知编码器与新增 LiDAR 条件都需要适配训练。

训练次序：准备带时间的专家轨迹及样条拟合 → 冻结 DeFM 训练投影/融合/扩散头 → 三模式闭环评估和难例补充 → 必要时小范围控制头微调。Vista、覆盖账本、几何可见性、Opt 核心与 Safety 不依赖学习训练。

共享网络不要求维护三套完整策略。若某模态的学习控制尚未验证，只能使用明确配置且经验证的替代执行后端，该模态不能因此获得学习控制通过声明。

## 10. 平滑、可执行与独立安全

候选为带物理时间的三次 B 样条。空间曲线、时间参数化、实际切换时刻和参考版本共同定义执行轨迹。三次样条在简单内部结点可达到 C2；跨重规划还需在预计交接时刻匹配位置、速度和加速度：

```text
τ_new(0)    = x_switch
τ̇_new(0)   = v_switch
τ̈_new(0)   = a_switch
```

交接状态结合尚在执行的轨迹和实时反馈，按实际结点向量及物理时间导数求边界控制点。只锚定首点或输入上一规划 token 不足以建立交接约束。三次样条的 jerk 通常分段，并可在内部结点跳变；额外交接约束只解决交接处的问题。第一版验收 C2 衔接与 jerk 上限。若任务要求全程 jerk 连续，应改用至少四次、简单内部结点的样条或更高阶表示，并核验交接导数。

轨迹可执行性按真实底盘运动学确定。非完整约束底盘不能沿任意侧向曲线直接运动；曲率、角速度和末端 yaw 必须与速度及转向能力兼容。固定 RGB-D 相机的观测朝向通过机器人姿态实现；若需要原地旋转，作为显式执行段验证其完整扫掠体与停车条件。

时间缩放与约束后的最终候选再交给独立 Safety，检查整个机器人扫掠体、悬空净空、地面连续性、运动学/制动、动态障碍、证据年龄、定位误差、停车区与参考有效期。轨迹离散采样需要误差裕度或自适应细分，不能只检查有限中心点。

高频跟踪器限制速度、角速度、加速度和 jerk，并处理参考迟到、跟踪偏差与期限违约。新轨迹无效时沿用仍有效且有停车余量的参考或停车。急停优先于平滑；全盲或未知不能靠统一 20% 膨胀证明安全，旋转同样受校验。

初始规划 8–10 Hz、跟踪 30–50 Hz、控制点数 8 属于设计预算，最终由 Orin 实测、底盘约束与制动能力冻结。

## 11. BT 节点与行为编排

复用 Autonomy 原生 BT 基类、注册和生命周期；探索专用节点位于自己的 plugins/action 与 plugins/condition。通用控制/装饰节点继续复用公共行为树目录。

核心八节点职责：

1. `SensorReady`：检查本模式的定位、观测、控制与安全能力。
2. `UpdateExploration`：有界消费输入，更新健康、预算、地图变化、覆盖和会话事件。
3. `SelectObservationPose`：分层覆盖选取下一个观测意图。
4. `AdaptObservationPose`：调用 Opt 并重新核验观测收益及要求。
5. `ObserveAtPose`：请求匹配身份的导航/观测；到达、朝向、独立有效帧及停留都满足后成功。
6. `CheckExplorationCompletion`：请求完成复核，依据实际证据进入收尾。
7. `ReturnToStart`：按配置请求返航并记录真实结果。
8. `SaveExplorationMap`：请求真实保存，核验对应版本的回执。

结构为：Update 持续监测 → 若已经收尾则返航/保存 → 否则检查 SensorReady → 完成复核或选点/适配/观测。导航、观测和保存等异步 action 返回 RUNNING，接受请求不等于成功。SensorReady 暂时不满足进入会话等待/恢复；终止结果由会话状态与结果政策确定。

Update 在导航和保存期间持续执行；暂停时 owner 仍处理健康、预算与输入。正常到达不自动触发 Spin/BackUp。接近区域的新证据由 Update 触发重验，无需把接近检查仅放在 FollowPath 已失败后的分支。

原生 `BeforeTick`/`BeforeTreeTick` 已有执行前检查，但实际运动还需同一可撤销 lease 贯穿 readiness、接受、树启动和 action dispatch。暂停树本身不会停止已经派发的异步控制。

开始/重规划先验证请求、几何和树资源，再进行可取消的服务准备等待，准备失败保留上一项已接受任务。当前 NavigationTask 已验证 XML 普通文件及请求内容；XML 内容和节点构造仍由原生 runner 在运行时校验，尚不具备接受前完整树构造验证。运动资格要在实际异步派发边界核验，并处理撤销与迟到接受；旧回调只可更新匹配请求。暂停与取消先撤销资格，再取消对应远端运动；恢复取得新的资格。取消无法确认时禁止派发新的运动。工作线程不得等待一个正被外部 join 的生命周期锁。

接受元数据只在领域接受后提交；新任务身份不能被旧结果污染。同位姿的新 task ID 仍是新任务，控制命令与 START/REPLAN 分别分类。检查与派发之间的并发窗口通过实际派发边界、撤销交接和晚接受取消关闭，不能用一次谓词检查代替。

实际派发采用明确的责任交接协议：先登记与本请求关联的取消责任，再提交一次发送资格；撤销后拒绝新的发送提交。已经提交、但仍阻塞在传输或尚未得到接受响应的请求继续保留取消责任，迟到接受后定向取消。门控锁不跨可能阻塞的传输调用，生命周期锁内只关闭资格，锁外发起取消，再等待线程退出和受控排空。这个协议确保取消责任不丢失，不承诺撤销瞬间已经提交的传输或物理运动立即停止。

取消 RPC 被接受只表明取消请求送达；运动排空需要目标拒绝或该目标的权威终态结果。取消异常、无效 future、拒绝或超时保留故障并阻止新运动，不能用清空本地句柄恢复资格。路径计算/平滑请求同样受撤销约束，但与真实运动分开记账，不用规划结果缺失制造底盘仍在运动的结论。恢复取得新代数，旧 ticket 和旧回调不能成为新请求的执行资格。物理停车还需要控制服务、反馈与底盘 watchdog 的独立契约和验收。

## 12. 完成判据、返航与保存

“完全探索”相对于固定任务范围、分辨率和传感器可观测要求；需要环境在确认期足够稳定、定位可靠、离散候选具有充分覆盖能力、公平处理和足够预算。没有建筑真值边界时报告终止证据与未确认清单，不输出整栋建筑 100% 承诺。

完成需要同时证明：实际账本无待兑现要求；frontier/重访均已处理；配置离散空间完成扫尾；图无路经过栅格复核；新有效观测下多轮稳定；相关输入、差分、图与覆盖处理到一致的有限截面；上游融合能够真实确认。

候选为空、传感器停止、预算耗尽或滚动窗口边界都不能证明完成。封闭门、无法观测材料和未评估区域保留原因及证据；若无法排除仍存在可达未探索空间，则结果保持 `INCOMPLETE_OBSERVATION`。

持续输入下锁定 `cut={lidar:n_lidar,rgbd:n_rgbd}`，各模块处理到这个有限前缀并检查真实融合依据。后续重复健康帧不无限重置完成；新增 frontier、必要质量/方向、相关几何或 epoch 改变撤销受影响结论。序号空洞与丢弃独立记录，不算覆盖。

保存绑定建图会话、已确认版本和完成凭据。保存期间继续监测，旧 ACK 不能覆盖更晚未完成工作。地图消费队列为空、等待一段时间或 MAP_CMD_SWITCH 都不能伪装为融合/保存回执；现有上游缺少能力时明确报告未完成或保存失败。

结果分别为 `exploration_outcome`、`return_outcome`、`map_save_outcome`。只有任务配置要求的三部分全部兑现才成功。时间/距离不足使用 `PARTIAL_BUDGET`；返航失败与保存失败分别记录；部分地图可以保存。手动 checkpoint 按版本保存并继续探索，最终保存绑定完成凭据。

预算持续预留下一任务、从该目标返航与裕度：`T_remaining >= T_next + T_return_from_next + T_margin`。返航路线失效则重算；缺少电池遥测时不声称能保证电量充足。

5. **控制到 Safety/跟踪**：TimedTrajectory 含控制点、结点向量、物理时间、交接状态、执行起时与有效期限；最终约束后轨迹才做扫掠体复核。
6. **观测/收尾到结果**：ObservationReceipt 提供实际质量与独立帧；CompletionEvidence 绑定任务要求、分来源有限截面、扫尾与真实融合；SaveReceipt 绑定建图会话、地图版本、保存产物及成功结果。
