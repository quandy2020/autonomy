## 1. 方案与任务边界

采用 FAR 的增量可见性图路线机制和 TARE 的全局/局部分层覆盖框架。公开路线插件为 **VistaPlanner**，实例名 `vista_planner`，放在 `autonomy/planning/planner/vista/`。探索放在 `autonomy/task/exploration/`，策略命名为 `HierarchicalCoverageStrategy`，没有 `tare/` 中间目录。

Opt 是观测目标位姿的适配组件；冻结 DeFM 提供深度特征；经过适配训练的 SanD 条件 B 样条头产生局部轨迹；独立 Safety 和跟踪器负责执行约束。原生 C++、Autolink、Protobuf 与 Autonomy BT，沿用 `.hpp/.cpp`、snake_case 路径及现有命名空间。FAR/TARE 的算法机制按这些接口适配，不搬入其 ROS 运行框架。

本版长程路线与探索调度由 Vista 和分层覆盖承担；早期 VNT-PA 姿态记忆方案不进入此版依赖。探索策略、全局路线、目标适配及局部控制分别具有明确接口。

`autonomy/map` 的代码、目录、接口和消息全部保持不变。既有建图链拥有地图；地图消费者、覆盖账本、可见图和局部执行几何分别维护在其他模块。

第一版任务为地面机器人在单层、允许且与起点连通的室内空间中，按固定分辨率完成可达/可观测几何覆盖，并按配置返航和保存。跨楼层、操作开门、类别语义任务和 RGB 纹理完整性不是默认几何任务的成功条件。

## 2. 架构与数据流

```text
3D LiDAR / RGB-D
        ↓ 时间、标定、有效性、健康状态
        ├── 上游定位建图 ──→ 现有 GridMap / Costmap
        │                          ↓ 消费者不可变读取与差分
        │                   Vista 增量可见图
        │                          ↓ 路线与访问成本
        ├── 原始几何 ──→ 实际覆盖账本 ──→ 分层覆盖策略
        │                                      ↓ ObservationGoal
        │                              Opt 调整与观测收益复核
        │                                      ↓ 唯一导航入口
        └── 深度视图 ──→ 冻结 DeFM ──→ SanD 局部轨迹
                                               ↓ 时间与边界约束
                                    Safety 扫掠体校验 → 跟踪执行
                                               ↓
                                      位姿反馈、实际观测确认
                                               ↓
                                    完成复核 → 返航 → 保存回执
```

所有权必须清楚：PlannerServer 是长期 Vista 图所有者；ExplorationTask 拥有一个 Session/Tree；Session 是唯一探索导航提交者；MappingTask/上游建图拥有地图更新与保存。独立 task/planning 进程通过 Autolink 路径服务调用同一图所有者，不共享跨进程插件指针，也不在 task 复制另一张全局可见图。

## 3. 三种传感器配置

- **`lidar_only`**：真实扫描束、量程、回波、时间与视野模型；独立可用的 LiDAR 定位链。原始点云/射线供覆盖和 Safety，学习支路投影为带标定与有效掩码的虚拟透视深度。不能默认所有 LiDAR 都是 360°，不能把投影空像素当自由空间。
- **`rgbd_only`**：RGB-D 定位链、米制深度、相机内外参和视锥；viewpoint 包含位置与 yaw。RGB 不自动产生类别语义，深度孔洞、透明或反光区域保持未知。
- **`lidar_rgbd`**：统一位姿基准，按各来源真实采样时刻变换，LiDAR 需要可用的运动补偿；分别评估视野，几何按稳定单元去重。冲突的有效障碍证据保守处理并安排重新观测。

配置模式与当前有效来源分开。联合模式降级继续必须同时满足剩余观测有效、定位可用、控制后端支持该模态、Safety 可完成。消息仍在发布不证明定位有效；模式滞回不延长已过期证据的执行资格。

覆盖政策启动时固定：默认 `GEOMETRY_ANY_SENSOR`，任一允许来源可兑现一份几何覆盖。若要求 `GEOMETRY_PER_SENSOR` 或多方向观测，则分别记账；传感器退出不会删除尚未兑现的要求。显式改变要求产生新版本。

## 4. map 零改动下的增量管理

MapReader 在真实安全读取入口取得自有不可变拷贝，维护 `map_epoch`、`geometry_revision`、`dirty_regions` 和分来源序列截面。这些是消费者契约，不增加 map 消息。

静态地图拷贝接口存在，不代表它就是在线建图最新数据；接入必须验证在线 GridMap/Costmap、mapper 输出与保存结果的来源。只有 2D 地图时，明确没有高度证据，不能填默认顶棚值制造三维净空。

覆盖历史、图连通性、当前执行证据分别管理。滚动窗口移出不表示障碍消失或任务完成；整图更新时间不能刷新旧单元的观测年龄。回环或坐标重置更新 epoch，可靠变换后复核，否则失效重建。

在 map 不变的约束下，第一版可通过安全拷贝和消费者差分实现图的增量更新；全图读取/比较仍有成本，不能把“图增量”宣传为整条数据链已经完全增量。

## 5. Vista 增量 visibility graph

节点来自障碍轮廓拐点、通行连接和临时起终点，保留稳定 ID。边保留几何来源、可通行/待验证状态及验证版本。

更新顺序为：变化分区 → 轮廓更新 → 节点匹配 → 受影响边校验 → 断边/重连 → 发布新图版本。边空间索引必须找到穿过变化区域的长边；仅检查端点会漏掉新障碍。障碍移走后，重新检查先前被阻挡的连接。

足迹膨胀只应用一次，避免错误封死窄门。可见图无路要用已知空间栅格连通搜索复核；图采样遗漏不能作为物理不可达的证明。包含未知段的高层路线只能作为未验证估计，当前执行段必须有有效几何证据。

## 6. TARE 分层覆盖与效率

全局 RegionManager 管理区域、覆盖进度与重访；VisitOrderOptimizer 用 Vista 的实际路线成本排序，计入转向、观测、重叠和返航。局部采样位置与观测方向，先做硬筛选，再按边际覆盖选择候选集并优化访问顺序。

效率来自分层调度、增量重算、边际收益去重、历史特征缓存和目标切换滞回。验证必须固定相同覆盖标准，比较任务时间、路程、重复行走和有效覆盖/米；启发式访问次序不承诺全局最优，降低覆盖或速度不能单独算效率提升。

公平扫尾独立于收益优先级。小 frontier、低收益角落、暂时受阻区域保持待处理；候选超出当轮预算时分页继续。地图变化只重新打开受影响项，不能每轮重置第一页导致后续项长期饥饿。

## 7. 信息增益的定义

第一版用**预计有效覆盖质量改善**，不称为严格 Shannon 熵下降。对覆盖类型 k 和候选位姿 q：

```text
G_k(q | S) = Σ_i A_i W_i [ max_s(V_i,s(q) Ĉ_i,s(q)) − B_i(S) ]+
U(q) = G(q) / (T_travel + T_turn + T_observe + ε)
```

`A_i` 是面积或标准化覆盖单元，`W_i` 是任务权重，`V` 表示视野/量程/遮挡，`Ĉ` 是相对于任务质量要求归一化的预测完成程度，`B_i(S)` 是真实观测与已选候选预测的最大完成程度，`[x]+ = max(0,x)`。

收益考虑未知边界、待补全表面、必要方向、距离、入射角、有效深度/回波、扫描密度、定位误差、运动与历史预测失败。不同类型按固定尺度归一化；原始点数不是面积。

每选一个 viewpoint 更新预计覆盖并集，再计算剩余候选的边际改善。同一单元的 LiDAR/RGB-D 重叠默认取 max 去重；分别要求来源时逐来源计算。未知遮挡后方不计为确定可见收益，门口潜在拓展价值和等待公平性属于调度优先级。后续若需要严格概率增益，可在消费者侧增加经过校准的后验与似然模型；map 零改动本身不禁止这种扩展，当前版本没有相应概率契约和标定证据。

示例：所需原始质量 0.8、实际已得 0.6，预测 0.4 的重复观测改善为 0，预测 0.7 的改善为 0.125。独立帧数、停留和必要方向单独兑现；质量改善为零不等于任务已完成。覆盖账本只接受实际有效观测，预测和到达都不能写入已覆盖。

收益先按任务约束硬筛选，再用于排序；预算不足、不可达、定位或执行证据过期的候选不能凭高收益胜出。必要方向和逐来源要求是独立账目维度，不能用总分抵消遗漏。ANY_SENSOR 的 max 是保守去重规则，互补视野通过不同单元增加收益；独立帧数、多视角和采样密度另行兑现，不假设两传感器误差独立而凭空累加置信度。

## 8. Opt 的最佳目标位姿调整

输入是 `ObservationGoal`，至少包含原始位姿、区域/frontier 关联、允许位移和 yaw、required_views、最低收益、必要覆盖单元及版本。Opt 搜索有限候选，按足迹/净空、已知可达性和任务约束硬筛选，再对可见性、观测质量、路线成本与调整代价排序。

适配后必须重新验证观测意图。一个安全可停靠但看不到指定 frontier 的点不是有效替代。“最佳”指在本次候选与约束中评分最高，不是连续空间全局最优。

`POINT_GOAL` 表示原任务可按目标执行；`REGION_FALLBACK` 表示在允许替代区域内仍能兑现原观测要求；`UNKNOWN_APPROACH` 表示到已知安全的观测位姿取得信息，不能把未知原始点直接认证为执行目标。路径临时受阻优先重规划/恢复，不直接替换有效目标。

## 9. DeFM 与 SanD：训练和连续执行

DeFM 全程冻结。每个新视图编码一次，缓存时间、位姿、标定和掩码。LiDAR 射线量程与相机轴向 Z 按模型转换；原始几何始终保留供覆盖与 Safety 使用。DeFM 特征本身不等于障碍实例、房间类别或自由空间证明；第一版几何区域、遮挡、地面和净空来自可验证的深度/射线处理，类别语义需要独立接入和验收。

第一版训练一套共享的模态条件投影/融合和 B 样条扩散头，数据包含三种模式、稀疏投影、孔洞、异步输入与模态缺失。三模式分别验收；不默认原 RGB-D 策略能直接用于 LiDAR。几何投影、Vista、覆盖策略和 Opt 核心无需学习训练。

局部候选带物理时间。在预计实际切换时刻约束新轨迹的位置、速度、加速度，使用实际结点向量的导数矩阵求边界控制点。三次样条内部简单结点可提供 C2 连续，但不自动保证跨重规划连续或 jerk 连续；内部 jerk 可分段跳变，交接 jerk 约束不解决内部结点。第一版验证 C2 衔接与 jerk 上限，全程 jerk 连续任务需要至少四次、简单内部结点的样条或更高阶表示。底盘非完整约束、角速度、末端 yaw 和显式原地观测旋转均需独立验证。N=8、8–10 Hz 规划、30–50 Hz 跟踪是初始预算，尚未成为 Orin 实测能力。

Safety 对最终时间化候选验证完整机器人扫掠体、悬空净空、地面连续性、动态障碍、证据年龄、定位误差、参考期限和停车区域。采样间隔需细分或误差裕度；未知和全盲不能靠固定膨胀系数证明安全。旋转也需扫掠体检查，急停优先于平滑。

## 10. BT 与异步任务契约

复用真实 `bt_node_base.hpp`、静态注册和原生生命周期。核心八节点为 SensorReady、UpdateExploration、SelectObservationPose、AdaptObservationPose、ObserveAtPose、CheckExplorationCompletion、ReturnToStart、SaveExplorationMap；操作、返回值和实际 XML 见详细设计 §12。

UpdateExploration 每轮有界处理输入；健康、预算、地图变化在导航与保存期间持续监测。选点/适配不发运动；ObserveAtPose 只有在对应导航到达、朝向、实际有效帧及停留均满足后才成功。正常成功路径不自动执行 Spin/BackUp。

耗时原生提交由独立派发器处理，BT owner 不被 readiness 等待阻塞。探索父任务拥有运动资格，委托导航继承该资格，外部抢占先撤销父资格并取消子执行。请求身份包含启动身份及 task/session/request/goal/epoch；同位置的新身份仍是新任务。

取消、暂停或抢占立即撤销旧 lease，恢复只发新 lease。原生 readiness、接受、BT 启动和实际执行入口持续校验许可；仅靠 tick 后回调或调用前一次检查不够。接受/取消责任在同一队列锁下交接，native Cancel 锁外执行；取消无法确认则禁止该代新运动。

原生 BtRunner 新增 `BeforeTick`，typed host 通过 `BeforeTreeTick` 转发，检查失败不执行该轮节点。取消及暂停/恢复可唤醒长周期等待；回调重入不会 self-join，标准/非标准异常与 halt 故障保留为失败。十一类真实 XML/节点效果的隔离专项已通过，并正式同步重编及纳入九项相关 CTest。详见 [BT 生命周期](native_bt_admission.md)。这项能力只约束树推进，不会自动停止已经派发的远端控制，也不能替代实际 dispatch 许可与取消回执。

Shutdown 先关闭入口和撤销许可，再排空提交/取消、销毁 owner 的 Session/Tree，最后释放导航/建图依赖。回调重入关闭只提出请求，由外部 owner join。初始化准备、暂停恢复、启动窗口与清理已通过 13 类隔离原生专项，并纳入正式构建和八项原生 CTest；原生导航领域接受已在 v2.12 接通并验证；实际执行许可、取消确认及父子任务调度仍需接通。

## 11. 完全探索的条件与无法保证时的结果

“完全”限定为：任务明确的允许区域、分辨率、机器人可达模型与配置传感器可观测范围。条件包括环境在确认期足够稳定、定位/观测可靠、有效候选最终被公平处理、有足够执行预算，以及真实上游融合和保存可确认。

完成需要无待兑现 frontier/观测要求、完整离散扫尾、对图无路的栅格复核，并在新的有效观测下多轮稳定确认。门口停靠不是房间探索完成；候选为空、预算结束、消息停止和窗口边界都不是完成依据。没有建筑真值边界时输出证据和未确认清单，不声称整栋建筑 100%。

完成保证相对于固定任务分辨率，且有前提。离散位置/方向集合必须对任务要求有足够覆盖能力，每个仍有效候选最终被处理并由实际观测确认；采样不充分时，即使公平遍历所有样本，也不能推出连续空间完全覆盖。封闭门、透明材质或传感器失效形成的不可确认区域不能静默排除；需要保留原因及证据，或显式修改允许范围和要求版本。

持续输入下锁定一个有限的分来源序列向量，检查上游输入队列、地图差分、图、覆盖与扫尾处理到该前缀，并等待真实融合依据。后续普通帧不无限重启确认；新工作、要求改变或 epoch 变化撤销旧完成候选。真实融合不可确认时保持 `INCOMPLETE_OBSERVATION`。

结果分别记录 `exploration_outcome`、`return_outcome`、`map_save_outcome`。只有配置要求全部兑现才成功；部分地图可保存。时间/距离不足为 `PARTIAL_BUDGET`，观测不足为 `INCOMPLETE_OBSERVATION`，返航/保存失败各自报告；缺少电量遥测不能承诺电量足够。

手动保存是不中断探索的版本化 checkpoint；最终保存绑定完成凭据。保存期间仍处理新证据，旧 ACK 不能覆盖更晚未完成工作。当前原型的任意多边形、部分覆盖政策及手动 checkpoint 尚未完成。

## 15. 接口与结果的审查契约

以下是目标接口必须表达的语义，不声称所有字段都已落入当前代码或 Protobuf：

- **SensorObservation**：来源、独立序号、实际采样时刻、标定版本、采样位姿、有效掩码、真实射线/深度与定位健康。空深度和无回波要区分有效最大量程与丢失数据。
- **MapReadView / RouteResult**：消费者拥有的不可变内容、frame、epoch、几何/图版本、受影响分区、请求身份。路线标出已验证与待验证部分；当前执行段必须另有新鲜证据。
- **ObservationGoal / AdaptationResult**：原目标、允许区域与位置/yaw 调整、必要单元和方向、最低质量/收益、要求版本及适配原因。原意图保留，调整后的路径和观测条件重新核验。
- **TimedTrajectory / MotionPermit**：物理时间、结点和控制点、执行切换时刻、参考版本、反馈状态、有效期限、父任务/会话/代数身份及可撤销许可。前次规划条件不能替代真实切换状态。
- **ObservationReceipt / CompletionEvidence / SaveReceipt**：实际独立观测及质量、分来源有限截面、完整扫尾、融合依据、排除/未确认清单、返航与保存版本。到达、树 SUCCESS、请求已提交分别不构成这些回执。

冻结任务策略：ANY_SENSOR 为默认；每来源与多方向要求显式配置。建议自主建图任务默认要求返航与最终保存，同时保留覆盖、返航、保存三个独立结果。用户取消后的保存仅按明确策略执行，不隐式发出运动。
