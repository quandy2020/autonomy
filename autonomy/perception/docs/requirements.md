# 需求与验收

## 功能范围

| 能力 | 需求 | 当前接入 |
|---|---|---|
| 基础视觉 | RGB 输入，输出检测、跟踪、分类、关键点、旋转框、实例或语义分割结果 | YOLO 系列及语义解码已有 C++ 路径。默认启用人员跟踪，其他头由配置启用 |
| 单目深度 | 输出与源图像对齐的米制深度，明确无效像素 | 默认启用 MoGe |
| 跟随 | 把人员轨迹和深度投影到地图系，提供目标、局部路径和栅格 | Follow 独立启动。支持可选语义障碍层 |
| 提示分割与三维占用 | 执行 SAM 2 与 FlashOcc 的兼容导出 | C++ 张量服务已有模型加载路径。提示准备、多相机同步及语义消息发布待接 |
| 房间轮廓 | 从占据栅格生成地图系轮廓和旋转矩形 | RRCE 服务支持兼容导出的原尺寸栅格输入，也支持预处理张量 |
| 三维物体 | 把 Boxer 的框转换成三维检测，再按房间轮廓标注归属 | C++ 服务支持包装导出结果。相机到地图变换由上游负责 |
| 语义探索 | 按房间标注聚合可达前沿，独立于几何图更新 | 房间归属代码已接到服务响应。稳定房间 ID、语义增量发布和 TARE 消费待接 |

## 系统约束

- 模型替换以输入布局、预处理、单位、输出张量和类别顺序为契约。目标机器需要实际可加载的 ONNX 或 TensorRT 文件。
- 观测携带源时间戳与坐标系。跟随使用深度帧时刻查询相机到地图的变换。房间归属还要求物体与房间快照的地图版本一致。
- 深度无效或语义缺失时保留未知语义。语义层可补充障碍证据，底盘制动及 FAR 几何图维护由各自的几何安全链路负责。
- 对象推理服务串行访问模型会话。部署时分别测量配对、预处理、推理、解码及端到端延迟，并记录目标硬件、模型版本和输入尺寸。仓库当前没有统一的实测时延基线。

## 验收场景

1. **模型兼容性**。用匹配的导出验证加载和单帧输出。用不存在的端口、错误类型和不匹配尺寸验证拒绝行为。
2. **跟随数据链**。回放交叉走位、遮挡和掉帧，记录轨迹 ID 切换、跟丢、输入时间差和 P95 延迟。检查深度、轨迹和相机内参坐标对齐。
3. **可通行性**。对比仅深度与语义融合网格，统计危险地形漏检和误封闭。检查语义障碍不会被跟随目标清除。
4. **房间几何**。用已知分辨率和旋转原点的栅格对照世界坐标。分别检查原始轮廓和旋转矩形。L 形房间的归属以轮廓判定。
5. **物体归属**。检查室内、边界、重叠区和不同地图版本。检查响应中的索引指向过滤后的三维检测数组。
6. **语义故障**。在语义探索集成后，停掉 RRCE 或 Boxer，检查几何可见图仍可更新，探索可回退到可达前沿。
