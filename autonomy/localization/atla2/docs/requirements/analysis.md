# 需求分析

## 1. 背景与问题

空中平台（多旋翼 / VTOL）需要在视觉、激光、IMU 等组合下提供实时位姿。既有方案常「一模式一套代码」，导致：

- 平台切换成本高  
- 传感器替换牵动算法层  
- 嵌入式与桌面双轨难以统一  
- 故障时缺少统一降级路径  

Atla2 目标：**一套后端与地图，VO/VIO/LIO/LIVO 配置装配**。

## 2. 干系人

| 角色 | 诉求 |
|------|------|
| 算法 | 可插拔前端、清晰因子接口、离线可复现 |
| 飞控 / 规划 | 稳定 `T_W_B`、协方差、状态（Tracking/Degraded/Lost） |
| 嵌入式 | 内存/算力预算、可降级、可交叉编译 |
| 测试 | 数据集评测、CI 回归、标定工具 |
| 运维 | 日志、配置版本、平台 YAML |

## 4. 非功能需求

| ID | 类别 | 要求 |
|----|------|------|
| N1 | 实时性 | 桌面 VIO ≥ 20 Hz；嵌入式 LIO 目标 ≥ 10 Hz（平台相关） |
| N2 | 内存 | 局部地图点数可配上限；超限降采样 |
| N3 | 可移植 | 核心无 ROS；ARM64 可编 |
| N4 | 可靠性 | 单传感器失效不崩溃；进入 Degraded |
| N5 | 可测性 | 离线合成可跑通；单测覆盖 config/factory |
| N6 | 可观测 | 状态机 + cov + benchmark 指标 |

## 5. 约束

- 依赖：Eigen、Ceres、OpenCV、yaml-cpp（经 autonomy localization FEATURES）  
- 许可证：Apache-2.0  
- 纳入 `autonomy_localization` 库，源码 glob，apps 单独 binary  

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 紧耦合延期 | 先松耦合交付 |
| 标定误差 | 标定工具 + 外参校验 |
| 嵌入式过热 | thermal 指标 + 降级 |
| 模式切换状态不一致 | 状态机 + 集成测试矩阵 |

## 7. 验收标准（摘要）

1. 四平台 YAML 均可 `atla2_offline --steps 100` 退出码 0  
2. `ctest -R atla2` 通过（BUILD_TEST=ON）  
3. 文档与目录树一致（本 docs 体系）  
4. 降级：去掉图像/雷达输入时进入 Degraded 而非崩溃
