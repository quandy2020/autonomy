# Atlas Voxel-SLAM 重构计划

目标：持续完善 Atlas 中无 ROS 的 Voxel-SLAM 复刻，最低 C++17，保持模块职责清楚、依赖可控，并采用 Google C++ 风格和完整语义命名。

## 阶段

1. **配置与全局状态隔离**：将优化参数作为显式配置传递，移除会导致并发调用互相覆盖的进程级状态，并校验数值和范围。
2. **对象与资源所有权**：收敛 Octree、关键帧点云、地图快照和异步 GBA 的所有权边界，优先使用 RAII，明确线程生命周期。
3. **并行任务架构**：形成独立的调度接口、任务状态与依赖表达和固定工作线程池；让 HBA 重用调度器，避免热点路径反复创建线程。
4. **模块边界与目录职责**：梳理 frontend、backend、map、optimization、sensor、common 的依赖方向，拆除跨模块隐式耦合和重复实现。
5. **命名与风格**：配置 Google C++ 格式；逐步消除新代码和重构代码中的非必要缩写，统一头文件、类型、函数和变量命名。
6. **验证与完成清单**：按模块核对实现、依赖和构建配置；在明确可用环境后验证 C++17 构建及算法运行，记录未验证项。

## 当前边界

不引入 ROS 依赖；维持最低 C++17。第三方算法缩写（如 SLAM、IMU、GTSAM）属于领域术语，可保留。重命名公开接口时同步更新仓库内调用方；必要时提供过渡兼容层。
