AMW + DDS 插件：选择核心边界

三种方案都保留 Autolink 的 Node / Reader / Writer API；区别在于 DDS 放在哪一层。

A

推荐：AMW 语义核心 + Transport 后端插件

稳定 API 边界

Node / Writer / Reader / Service / Action

↓ AMW Core：命名、QoS 归一化、拓扑、路由策略、序列化契约

↓ Transport Provider ABI

INTRA  |  SHM  |  Fast DDS  |  Cyclone DDS

业务 API 稳定；各 DDS 仅实现 Provider；可按节点关系选择后端。

B

严格 RMW：进程启动时选一个 DDS

单一运行时实现

Autolink API

↓ AMW / RMW ABI

Fast DDS 或 Cyclone DDS

实现与测试最简单，但不能在同一进程混用 SHM 与不同 DDS。

C

桥接优先：核心保持本地 SHM

生态适配进程

Autolink INTRA / SHM ↔ Bridge ↔ ROS 2 / DDS

最小风险、最容易对接 ROS 2；跨机路径多一次序列化和转发。
